Apply AFTER Online World Consistency & Persistent Rocks (21-file delta). Use the complete source if the delta order is uncertain. Deploy frontend AND Netlify Functions together, reopen both clients and use a fresh room. No new env variables, dependencies, Firebase rules or database reset are required.

## What changed
- Select cake/chili/watermelon/grenade in the right inventory. Selection is immediate and does not consume an item or send an HTTP request. Hit fires the equipped weapon. Hold Hit to repeat food weapons while stock remains. Empty weapons are clearly labeled and Hit is disabled until another weapon is selected. Spinach/crafting/lift/place/throw remain explicit utility actions.
- Cake color selection is immediate too. The selected color travels with Hit and is validated in the same authoritative transaction, avoiding a separate color-selection request race.
- The center cake palette was moved into the right inventory. The flyout uses three columns in landscape and bounded internal scrolling on short screens. It closes after weapon selection; inventory and voice flyouts close each other to reduce overlap. No full 3D/mobile browser layout QA was available; source CSS and unit/build checks do not replace a physical-device test.
- Chili consumes one item per burst and creates eleven flame lanes, expanding into a broad cone, with roughly six units of reach. Watermelon consumes one item per ten-seed burst; seeds are staggered by 65ms and travel faster with an elongated seed appearance. Shared shot generation is used by the server and local presentation. Fast projectiles use swept collision checks instead of testing only their next endpoint.
- Commands accepted during an outstanding request enter a bounded FIFO (one executing plus one waiting). Item actions no longer disappear solely because the previous request is running. The right-side status shows pending confirmations. Movement polling yields to queued actions so it cannot repeatedly take priority over them. Queue capacity, stock and cooldown still limit input; no unbounded command backlog is allowed.
- Online attacks no longer call the resource-changing local throwCake before server acceptance. Immediate local projectiles and impacts are visual feedback only: no damage, death, loot, grass harvesting or inventory spending is awarded by that feedback. Stock reservations prevent multiple pending attacks from using the same available item. The server remains authoritative. Own authoritative projectiles are hidden in presentation to avoid displaying the same shot twice; shared teammate/enemy projectiles remain visible.
- Guardian presentation predicts existing patrol motion for at most 1.25 seconds after the latest snapshot and blends corrections. It does not modify authoritative guardian positions, HP, combat, rewards or collision state. Dead guardians are hidden according to confirmed server state.

## Important unresolved limit
This is NOT a migration to a continuous realtime simulation server. Adventure still uses authenticated HTTP Function requests to advance/confirm gameplay. If those requests take several seconds, confirmed damage, pickups and state still arrive late. Guardian prediction stops after 1.25 seconds rather than inventing indefinite AI motion. A player can therefore still see waiting/holding/corrections when updates are too late. These presentation/input fixes do not prove production latency is solved or make online equivalent to Solo.

For consistently Solo-like online responsiveness, the next architectural step is a continuously running authoritative room server with a persistent transport, frequent snapshots, client prediction and server-side lag compensation. See docs/REALTIME_GAMEPLAN.md. That server has NOT been deployed or implemented in this release; no new hosting service/account was configured. Existing Firebase login, profiles and durable data should remain in use.

Existing Movement confirmation timing console output and Server-Timing auth/profile/room headers remain available. Inspect real move/ability request timing on the deployed site to identify whether authentication, profile reads, room processing or network is dominant. No production timings were captured in this environment.
